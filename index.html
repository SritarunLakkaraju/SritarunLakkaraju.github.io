About me

I build things, then I prove they work.

I’m Sritarun, an M.Tech student in AI and Data Science who works across the stack, from LLM agents down to SIMD kernels.

I’m studying at Mahindra University, Hyderabad (2025–2027). Before that I completed a B.Tech in Computer Science and Engineering at MVSR Engineering College (Osmania University) and a micro-credit programme in Computer Science at Daksh Gurukul, IIT Guwahati.

Most of my recent work is AI engineering: tool-calling agents on Google ADK, LangGraph and CrewAI, hybrid-retrieval RAG measured on labelled evals, and guards that stop a model from inventing numbers. I also build complete products: React and Flutter front ends, FastAPI and Firebase back ends, and the tests and data layer between them.

Underneath that, I like knowing how things run on the metal. I wrote a series of five C++17 projects that build on each other, from a matrix multiply that reaches 693 GFLOPS on 11 cores to a small inference engine that matches PyTorch on all 10,000 MNIST test images.

What ties it together is a habit: I measure what I build, report the misses as well as the wins, and write things down clearly enough that someone else can reproduce them.

LedgerLock

Three-Way Payment Settlement Reconciler

0false matches on 300 seeded orders

Built for the Razorpay Buildathon (AI Finance Controller track): reconciles a merchant's orders, Razorpay settlement report and bank statement three ways, joining on order id, payment id and UTR.

How it works (6 more)
  • Wrote a deterministic matching engine with money in integer paise and explicit rule tables. On a seeded dataset of 300 orders it auto-matches 96.7% with 0 false matches and 100% reason-code accuracy, scored against ground truth the engine never reads.
  • Let the LLM only narrate exceptions, never compute them: a guard pulls every numeral from the model's reply and falls back to a template if any number was not in the input.
  • Gave every unresolved record a fixed reason code, an evidence trace and a plain-English explanation with a suggested next step, so a finance user can see why a payment did not match without reading code.
  • Covered it with 51 pytest tests (money math, all 11 injected anomaly types, a golden seed-42 regression run) and exposed it through a FastAPI REST API with OpenAPI docs and a React UI.
  • Made every result reproducible: one command (make demo SEED=42) regenerates byte-identical input files and the exact metrics, which a golden regression test pins down.
  • Wrote a seeded synthetic-data generator for orders, settlements and bank rows with 11 labelled anomaly types (refunds in later settlements, duplicate UTRs, rounding drift); same seed gives byte-identical CSVs.

DealMind

Deal-Intelligence Agent with Long-Term Memory

4cooperating agents with long-term memory

Built a sales co-pilot for HackWithHyderabad 3.0 that remembers every call and email in a deal, writes a cited pre-call brief, coaches the rep live on objections, and learns across deals which tactics actually win.

How it works (6 more)
  • Split the work across four agents (extractor, briefing, live coach, learning) behind a FastAPI backend with a React front end over REST and SSE; the brief runs three memory recalls and a reflect call in parallel.
  • Designed the memory layout as per-deal, team-playbook and per-rep banks. Thumbs-up/down feedback and closed deals write outcomes back to the playbook, so the next recommendation actually changes.
  • Grounded every brief in retrieved context (retrieval-augmented generation): three semantic recalls run in parallel with asyncio over per-deal, team-playbook and per-rep memory banks feed the LLM, so every claim in the brief links back to the memory it came from.
  • Made LLM output dependable without function calling: JSON mode, then Pydantic validation, one repair call, a fallback model and finally a schema-valid degraded result. The server drops any citation the model invents.
  • Handled failure paths: failed memory writes queue in SQLite and replay at startup, re-ingest is idempotent by document id, and emails and phone numbers are scrubbed before anything is stored.
  • Made failures visible instead of silent: the UI shows whether the memory service is connected and, if not, why, and a banner appears whenever it goes down, so users and support can tell at a glance what is wrong.

Fast GEMM

Matrix Multiplication from Scratch

48×faster than a naive loop on one core

Took single-precision matrix multiply from a naive triple loop (2.3 GFLOPS) to a BLIS-style packed kernel with an 8x12 register-blocked NEON micro-kernel (109.7 GFLOPS at n = 1000), a 48x speedup that lands within 5% of single-thread OpenBLAS on large matrices.

How it works (2 more)
  • Parallelised the outer block loop with OpenMP using a dynamic schedule so the slower efficiency cores simply take fewer blocks; the kernel reaches 693 GFLOPS on 11 cores, while the OpenBLAS build tops out at 544.
  • Tracked down a slowdown at power-of-two sizes (36 vs 61 GFLOPS) that fits cache-set conflicts between tile rows, and removed it with operand packing. Every variant is checked against OpenBLAS in the same run that times it.

How it works (3 more)

Conv2D Kernels

Direct, im2col + GEMM and Winograd

1.87×Winograd over im2col on deeper layers

Implemented 3x3 convolution three ways (direct NEON, im2col + GEMM, Winograd F(2x2, 3x3)) and benchmarked them on five VGG-style layer shapes. Winograd is up to 1.87x faster than im2col on deeper layers; direct wins when there are only 3 input channels.

How it works (2 more)
  • Measured what fusing conv + bias + ReLU into one pass is worth: 1.72x when the output tensor is 64 MB, no measurable gain on layers with 64 or more input channels.
  • Wrote the Winograd transforms as C++ templates instantiated for both float and float32x4_t, so the scalar and SIMD paths come from one source; all outputs are checked against a naive reference.

INT8 Quantised Kernels and Post-Training Quantisation

3.7×INT8 SDOT over the FP32 kernel

Wrote an int8 x int8 to int32 matrix multiply on the ARM SDOT dot-product instruction, with an 8x12 micro-kernel held in 24 registers: 405.9 GOPS on one core (3.7x the FP32 kernel) and 2.14 TOPS on 11 threads.

How it works (2 more)
  • Applied post-training quantisation to the MNIST CNN (per-tensor symmetric weights, min/max-calibrated activations, zero point folded into the bias): accuracy held at 98.73% on the 9,000 images not used for calibration, 99.90% of predictions agree with FP32, and weights shrank from 808 KB to 203 KB.
  • Showed that int8 is not automatically fast: without the dot-product instruction, the widening kernel ran 2.8x slower than FP32, and the tiny network gained only 1.2x end to end because packing and requantisation dominate.

Transformer Kernels

Softmax, LayerNorm and Attention

24×faster attention than naive loops

Wrote NEON softmax, LayerNorm and multi-head attention with scalar references; a vectorised exp has max relative error 8.4e-8 over 8 million inputs, softmax runs 3.3-3.5x and LayerNorm 3.9-8.3x faster than the stable scalar versions.

How it works (2 more)

  • Demonstrated numerical stability instead of assuming it: the textbook softmax returns NaN on large logits and one-pass variance breaks down at large offsets, while the two-pass NEON LayerNorm stays within 5.1e-4 of float64.
